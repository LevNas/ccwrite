# 日本語 Markdown の描画で崩れる書き方

ここに挙げる崩れは、どれもエラーにならず、ソースを読んでいる側には見えません。描画して初めて分かるため、機械で検査します。
作業中のリポジトリに Markdown 規約があれば、そちらを優先します。

## 強調（太字）

日本語では、**強調の中身を約物（`）` `」` `。` `：` など）で始めない・終わらせない**。
GFM は、開き `**` の直前が文字で直後が約物のとき開きと認めず、閉じ `**` の直前が約物で直後が文字のとき閉じと認めません（CommonMark の flanking 条件）。
条件を外すとアスタリスクが生のまま描画されます。

| 書き方 | 結果 |
|--------|------|
| `は**「重要」**の話` | ❌ 開きが成立しない |
| `を**A（B）**で認証する` | ❌ 閉じが成立しない |
| `を**A（B）まで**で認証する` | ✅ 中身の末尾を文字にする |
| `は **「重要」** の話` | ✅ 強調の外側に半角スペースを置く |
| `**強調です。**`（行末・段落末） | ✅ 直後が改行なら約物で終わってよい |

回避は 2 つです。中身の先頭と末尾を文字にする（「まで」「の話」などを強調の内側へ入れる）か、強調の外側に半角スペースを置くかです。前者を優先します。

## 段落の途中の改行（一文一行で書くリポジトリ）

GFM は段落の途中の改行を「ソフト改行」として扱い、描画時に前後の行を 1 行へ連結します。

- **段落の中で改行を見せる**: 行末に半角スペースを 2 つ置いてから改行する（`<br>` として描画される）
- **段落を変える**: 1 行空ける（新しい `<p>` として描画される）。空行で区切る段落の間には行末スペースは要らない
- **一文一行で書くリポジトリ**: 「。」ごとに行を分け、文末に半角スペース 2 つを置く

スペースが落ちると、複数の文が 1 行へ連結されます。ソースでは一文一行に見えるため、書いた本人は気づけません。

段落の途中に 1 行挿入したときは、直前の行も確かめます。挿入によって直前の行が新たに行末スペースを必要としますが、その行自体は差分に出ないためです。

## 表のセル内の改行

- セル内で改行するときは `<br>` を使う（行末スペースは表の中では効かない）。セル内に複数の文があるときも「。」ごとに `<br>` で区切る
- セル内の列挙は `<ul><li>…</li></ul>` を使う。ただし Markdown リンクや `` `コード` `` を含むときは `<br>` 区切りにする（HTML ブロックの中では Markdown が処理されない場合があるため）
- 長い文をどこで折るかは、`japanese-writing-router` の budouX の節に従う

## メールアドレスと「#数字」

- メールアドレスはバッククォートで囲む（例: `user@example.com`）。囲まないと、GitHub や GitLab が自動で mailto リンクにする
- GitHub や GitLab では、`#数字` が自動的に issue へのリンクになる。issue 番号でない連番は `No.1` のように書くか、バッククォートで囲む（`` `#5` ``）

## 読み手に配慮したラベル

- 「やさしい説明」のような、読み手によっては見下されたと感じうる見出し・ラベルを使わない（「用語説明」などの中立な言い方にする）
- 平易な言葉で書くこと自体は続ける。配慮するのは内容の平易さではなく、ラベルの付け方

## 検査

ccwrite は 3 つの方法で同じ検査（`scripts/mdcheck.py`）を走らせます。

### 編集のたび（hook、既定で有効）

`.md` を Write か Edit で書き換えると、**その編集で追加した行だけ**を検査し、見つけたときだけ Claude に警告します。編集は止めません。警告を受けたら、その場で直します。

| 検査 | 既定 | 切り替え（リポジトリの `.claude/settings.json` の `env`） |
|---|---|---|
| 強調 | 有効（pandoc が無いと何もしない） | `"CCWRITE_EMPHASIS": "0"` で無効 |
| 行末スペース | 無効 | `"CCWRITE_LINEBREAKS": "1"` で有効（一文一行で書くリポジトリ向け） |

強調の判定は、CommonMark の規則を自前で実装せず、pandoc に描画させて `**` が残るかで決めます。pandoc が入っていない環境では、強調の検査は何も言いません。

### 手で走らせる（ファイル全体）

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/mdcheck.py" <file.md>                  # 強調
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/mdcheck.py" --linebreaks <file.md>     # 強調と行末スペース
```

書き終わったときと、訂正したときの両方で走らせます。訂正で足した文が崩れを持ち込むためです。

### コミットのたび（pre-commit、任意）

`${CLAUDE_PLUGIN_ROOT}/hooks/pre-commit.sample` を `.git/hooks/pre-commit` にコピーすると、ステージした `.md` の追加行を検査し、見つけたらコミットを止めます。設定はファイル冒頭のコメントにあります。

追加行だけを見るのは、既存の違反が残るリポジトリで、別件で 1 行直しただけのコミットが止まらないようにするためです。止められた側が `--no-verify` を常用すると、検査全体が形骸化します。既存の違反は、次にその文書を触るときに直します。
